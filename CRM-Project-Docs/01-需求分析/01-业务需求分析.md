## 一、项目背景与目标

### 1.1 业务背景

**现状问题：**
某中小型企业（50-200人），销售团队20人，目前使用Excel表格管理客户信息，面临以下痛点：

| 痛点 | 具体表现 | 影响 |
|------|---------|------|
| 📊 数据分散 | 每个销售有自己的Excel，客户信息分散在各个文件中 | 无法统一查看客户数据，重复跟进 |
| 🔒 权限混乱 | 所有人都能看到所有客户信息，离职员工带走客户 | 商业机密泄露风险高 |
| 📈 无法追踪 | 不知道客户处于哪个销售阶段，跟进记录不完整 | 销售转化率低，管理层无法决策 |
| ⏰ 效率低下 | 手工录入、查找困难、统计报表耗时 | 销售人员每天浪费1-2小时在数据整理 |
| 📱 移动办公难 | Excel在手机上难以操作 | 外出拜访客户时无法及时记录 |

**案例场景：**
```
销售小李的一天（使用Excel前）：
08:30 - 打开电脑，找到昨天的客户Excel表格
09:00 - 想查"上周约好今天回访"的客户，手动翻看备注列
09:30 - 发现同事小王也在跟进同一个客户（数据重复）
10:00 - 领导要本月销售数据，开始手工统计...
12:00 - 还在做报表，午饭都顾不上吃
```

### 1.2 项目目标

**核心目标：** 建立一套统一的客户管理系统，提升销售效率30%以上

**具体目标：**
1. ✅ **数据集中化** - 所有客户信息存储在一个系统中，随时查看
2. ✅ **流程规范化** - 明确客户从"潜在→成交"的每个阶段和操作
3. ✅ **权限精细化** - 谁能看什么数据，谁能做什么操作，清晰可控
4. ✅ **分析自动化** - 系统自动生成报表，管理层实时掌握销售情况
5. ✅ **移动便捷化** - 手机也能轻松录入和查看客户信息

**成功标准：**
- 客户信息录入时间从10分钟降至3分钟
- 销售漏斗转化率可量化追踪
- 管理层每周查看销售报表时间从2小时降至10分钟
- 客户跟进记录完整率达90%以上

## 二、用户角色分析

### 2.1 角色定义

系统设计4种用户角色，每个角色的需求和权限不同：

#### 👨‍💼 角色1：销售人员（Primary User）
**人物画像：** 小李，25岁，入职1年，负责开发新客户
**日常工作：** 打电话、拜访客户、记录跟进情况、维护老客户关系

**核心需求：**
- 快速录入客户信息（姓名、电话、公司、需求）
- 查看自己的客户列表，按"今日待跟进"、"本周重点"分类
- 记录每次沟通的内容和结果
- 移动客户的销售阶段（潜在客户→意向客户→成交）
- 设置跟进提醒（明天上午回访张总）
- 查看自己的业绩统计

**使用频率：** 每天使用10+次，单次操作3-5分钟

---

#### 👔 角色2：销售经理（Manager）
**人物画像：** 王经理，35岁，管理5人销售团队
**日常工作：** 分配客户资源、监督团队进度、分析销售数据、制定策略

**核心需求：**
- 查看团队所有客户信息和跟进状态
- 分配客户给不同销售（公海池功能）
- 查看团队销售漏斗（多少潜在客户、多少在洽谈、转化率）
- 导出销售报表给上级
- 查看个人销售业绩排名
- 设置销售目标和考核指标

**使用频率：** 每天使用3-5次，单次操作10-20分钟

---

#### 👨‍💻 角色3：系统管理员（Admin）
**人物画像：** IT部门小张，负责系统维护
**日常工作：** 添加/删除用户、分配权限、配置系统参数

**核心需求：**
- 管理所有用户账号（新员工入职开通账号，离职员工删除）
- 设置角色权限（销售只能看自己的客户，经理能看团队数据）
- 配置系统参数（销售阶段名称、客户来源分类）
- 查看系统操作日志（谁在什么时间做了什么）
- 数据备份和恢复

**使用频率：** 每周使用1-2次，单次操作20-30分钟

---

#### 👨‍💼 角色4：高层管理者（Executive）
**人物画像：** 李总，公司副总，分管销售部门
**日常工作：** 查看整体销售数据，做战略决策

**核心需求：**
- 查看公司级别的销售数据（只看不改）
- 查看销售趋势图（本月、本季度、本年度）
- 对比不同团队的业绩
- 查看客户来源分析（哪个渠道效果最好）
- 导出高层决策报表

**使用频率：** 每周使用1次，单次操作5-10分钟

## 三、核心业务流程

### 3.1 客户生命周期流程

**完整流程图：**
```
        获取线索              初次接触             需求确认            商务洽谈            合同签订           售后服务
         ┌─┐                  ┌─┐                 ┌─┐                ┌─┐                ┌─┐               ┌─┐
  ───────►│ │─────────────────►│ │────────────────►│ │───────────────►│ │───────────────►│ │──────────────►│ │
         └─┘                  └─┘                 └─┘                └─┘                └─┘               └─┘
      潜在客户(Leads)      意向客户(Prospects)   需求客户(Qualified)  洽谈客户(Negotiation) 成交客户(Won)    老客户(Existing)
      
      获取方式：              转化条件：            转化条件：          转化条件：            转化条件：         复购可能：
      - 展会名片              - 已电话联系          - 明确需求           - 报价发送            - 合同签署        - 持续跟进
      - 网站留言              - 确认有需求          - 预算确认           - 价格谈妥            - 首付到账        - 新品推荐
      - 电话外呼              - 添加微信            - 决策人对接         - 合同审批中          - 项目启动        - 增值服务
      - 客户推荐                                                                        
      
      平均停留时间：           平均停留时间：         平均停留时间：       平均停留时间：         目标：
      1-3天                   7-15天                5-10天              10-20天               长期维护
      
      流失率：70%             流失率：40%            流失率：30%          流失率：20%           复购率：35%
```

**详细阶段说明：**

#### 阶段1：潜在客户（Leads）
**定义：** 刚获取到联系方式，还未深入沟通的客户

**来源渠道：**
- 展会收集的名片
- 官网留言表单
- 400电话咨询
- 朋友推荐
- 行业论坛

**销售动作：**
1. 24小时内首次致电（黄金48小时原则）
2. 确认客户基本信息（公司规模、行业、职位）
3. 判断是否为目标客户（有预算、有需求、有决策权）
4. 添加微信/邮箱，发送公司介绍资料

**系统记录：**
- 客户来源
- 首次接触时间
- 初步需求判断
- 下次跟进计划

**转化目标：** 3天内判断是否有效客户，有效则进入下一阶段，无效则放入公海池

---

#### 阶段2：意向客户（Prospects）
**定义：** 已确认有需求，正在了解产品的客户

**客户特征：**
- 接听电话，愿意沟通
- 明确表达有类似需求
- 要求发送产品资料或报价
- 同意添加微信保持联系

**销售动作：**
1. 发送详细产品介绍（PDF/视频）
2. 预约产品演示（线上或线下）
3. 了解客户具体使用场景
4. 判断预算范围
5. 识别决策人和决策链

**系统记录：**
- 需求描述（要解决什么问题）
- 预算范围（3-5万、5-10万、10万以上）
- 决策流程（谁说了算）
- 竞争对手（是否在对比其他供应商）
- 期望成交时间

**转化目标：** 15天内完成需求确认和产品演示，进入需求客户阶段

---

#### 阶段3：需求客户（Qualified）
**定义：** 需求明确，预算落实，即将报价的客户

**客户特征：**
- 已完成产品演示，反馈积极
- 明确具体需求清单
- 预算已申请或确认
- 决策人已对接

**销售动作：**
1. 提供详细解决方案（针对客户场景定制）
2. 发送正式报价单
3. 解答报价相关疑问
4. 邀请客户到公司参观（建立信任）
5. 提供成功案例和客户见证

**系统记录：**
- 报价方案内容
- 报价金额
- 客户反馈意见
- 竞品对比情况
- 预计签约时间

**转化目标：** 10天内推动客户进入商务洽谈

---

#### 阶段4：洽谈客户（Negotiation）
**定义：** 已报价,正在谈判价格/合同条款的客户

**客户特征：**
- 认可产品方案
- 在讨论价格、付款方式、服务条款
- 合同在走内部审批流程

**销售动作：**
1. 价格谈判（给出折扣底线）
2. 合同条款沟通（付款方式、售后服务）
3. 处理客户内部审批流程
4. 跟进合同签署进度
5. 准备合同盖章

**系统记录：**
- 最终成交价格
- 付款方式（全款/分期）
- 合同审批状态
- 预计签约日期
- 是否需要上级审批

**转化目标：** 20天内完成合同签署

---

#### 阶段5：成交客户（Won）
**定义：** 已签合同，完成首付款的客户

**客户特征：**
- 合同已签署
- 首付款已到账
- 项目正式启动

**销售动作：**
1. 移交项目组实施
2. 定期跟进项目进度
3. 解决实施中的问题
4. 验收确认
5. 收取尾款

**系统记录：**
- 合同编号
- 合同金额
- 回款记录（首付、尾款）
- 项目状态
- 验收时间

**维护目标：** 长期维护，争取复购和转介绍

---

#### 阶段6：老客户（Existing Customer）
**定义：** 项目交付完成的客户

**维护策略：**
- 定期回访（季度/半年）
- 新产品推荐
- 行业资讯分享
- 邀请参加客户活动
- 争取转介绍

### 3.2 典型业务场景流程

#### 场景1：新线索录入流程
```
销售小李参加行业展会，收集了30张名片

第1步：展会当晚，小李打开CRM手机端
第2步：点击"添加客户"按钮
第3步：拍照识别名片（系统自动提取姓名、电话、公司）
第4步：手动补充信息（从哪个展会获取、初步需求）
第5步：选择"潜在客户"阶段
第6步：设置提醒（明天上午致电）
第7步：保存成功

系统操作：
- 自动分配客户编号（C202501120001）
- 记录创建人（小李）
- 记录创建时间（2025-01-12 20:30）
- 在"今日待办"中显示"明天上午致电张总"
```

#### 场景2：客户跟进记录流程
```
销售小李今天致电客户张总

第1步：小李在CRM中找到"张总"的客户卡片
第2步：点击"添加跟进记录"
第3步：记录沟通内容：
       - 沟通方式：电话
       - 沟通时间：2025-01-13 10:30
       - 沟通内容：张总表示对产品感兴趣，要求发送详细资料
       - 客户反馈：预算5-8万，3月前要采购
       - 下次跟进：发送资料后，周五再次致电确认
第4步：修改客户阶段为"意向客户"
第5步：设置下次跟进时间（本周五上午）
第6步：保存

系统操作：
- 在客户详情页显示"跟进记录时间轴"
- 客户卡片显示"最后跟进时间：1月13日"
- 在销售漏斗看板中，将张总从"潜在客户"列移动到"意向客户"列
- 在小李的"本周待办"中添加"周五致电张总"
```

#### 场景3：销售经理查看团队数据流程
```
王经理每周一早会前查看团队数据

第1步：王经理登录CRM系统
第2步：进入"数据分析"模块
第3步：选择"团队视图"
第4步：查看销售漏斗：
       - 潜在客户：150个
       - 意向客户：60个
       - 需求客户：25个
       - 洽谈客户：10个
       - 本周成交：3个
       - 转化率：2%（行业平均3%，需要提升）
第5步：点击"个人业绩排名"
       - 小李：本月新增客户20个，成交2个
       - 小王：本月新增客户15个，成交3个
       - ...
第6步：发现小李的意向客户很多但转化率低
第7步：点击小李的客户列表，查看具体客户跟进情况
第8步：发现部分客户已经超过15天未跟进
第9步：导出"超期未跟进客户列表"，准备早会讨论

系统操作：
- 实时计算团队数据
- 生成可视化图表（柱状图、折线图、饼图）
- 支持按日期筛选（本周、本月、本季度）
- 导出Excel报表
```

#### 场景4：公海池领取客户流程
```
销售小王今天业绩完成，想多开发客户

第1步：小王进入"公海池"模块
第2步：查看公海池客户列表（系统规则：超过30天未跟进的客户自动进入公海）
第3步：看到3条客户信息：
       - 张总（某科技公司，预算5-8万，原负责人：小李，进入公海原因：30天未跟进）
       - 李经理（某贸易公司，预算3-5万，原负责人：小刘，进入公海原因：小刘已离职）
       - 王总（某制造企业，预算10万+，原负责人：小陈，进入公海原因：客户明确拒绝）
第4步：小王点击"张总"的详情，查看历史跟进记录
第5步：觉得这个客户有机会，点击"领取客户"
第6步：系统弹出确认对话框："确定领取该客户？领取后需在7天内完成首次跟进"
第7步：确认领取

系统操作：
- 将客户负责人从"小李"改为"小王"
- 记录领取日志（小王于2025-01-13从公海池领取客户张总）
- 在小王的"今日待办"中添加"7日内首次跟进张总"
- 给小李发送通知（您的客户张总已被小王从公海池领取）
```

## 四、功能需求详解

### 4.1 客户管理模块

#### 功能1：客户信息录入
**需求描述：** 销售人员能快速录入客户基本信息和业务信息

**输入内容：**

**基本信息（必填）：**
- 客户姓名（中文2-20字符，支持空格）
- 手机号码（11位数字，格式验证）
- 公司名称（2-50字符）

**基本信息（选填）：**
- 公司电话（固定电话格式）
- 邮箱地址（邮箱格式验证）
- 职位（下拉选择：董事长、总经理、部门经理、员工、其他）
- 微信号
- QQ号
- 公司地址
- 公司网址

**业务信息（必填）：**
- 客户来源（下拉选择：展会、官网、电话、推荐、其他）
- 所属行业（下拉选择：科技、贸易、制造、教育、医疗、其他）
- 销售阶段（默认为"潜在客户"）

**业务信息（选填）：**
- 客户标签（可多选：重点客户、VIP、潜力大、老客户、预算充足）
- 预算范围（下拉选择：3万以下、3-5万、5-10万、10万以上）
- 期望成交时间（日期选择器）

#### 功能3：客户价值分析

1. **成交金额**（已成交客户）
2. **预算范围**（未成交客户）
3. **跟进次数**（跟进越多，意向越强）
4. **响应积极度**（客户反馈是否积极）
5. **决策权重**（是否为决策人）

**客户分级：**
- 🌟🌟🌟 A级客户（高价值）：预算10万+，决策人对接，跟进5次以上

- 🌟 C级客户（一般价值）：预算5万以下，普通员工，跟进少

**应用建议：**
- A级客户：销售经理亲自跟进，提供定制化方案
- B级客户：骨干销售跟进，保持高频沟通
- C级客户：新手销售练手，降低跟进频率

## 六、业务规则

### 6.1 客户管理规则

1. **客户唯一性**：手机号作为唯一标识，不允许重复
2. **客户归属**：客户只能有1个负责人，转移后归属新负责人
3. **客户保护期**：客户分配给销售后，30天内不得转移（离职除外）
4. **客户回收**：超过30天未跟进的客户自动进入公海池
5. **公海池领取限制**：每人每月最多领取20个客户
6. **首次跟进要求**：从公海池领取客户后，7天内必须首次跟进

---

### 6.2 销售阶段规则

1. **阶段流转**：客户阶段可以前进或后退（如从"洽谈客户"退回"需求客户"）
2. **阶段停留时间**：
   - 潜在客户：建议3天内判断是否有效
   - 意向客户：建议15天内完成产品演示
   - 需求客户：建议10天内完成报价
   - 洽谈客户：建议20天内完成签约
3. **超期预警**：超过建议停留时间，系统红色预警提示

---

### 6.3 权限规则

1. **数据隔离**：销售人员只能看自己的客户，销售经理能看团队客户
2. **操作限制**：销售人员不能删除客户，只能编辑自己的客户
3. **角色唯一**：每个用户只能有1个角色
4. **管理员保护**：系统管理员至少保留1个，防止误删

---

### 6.4 数据统计规则

1. **成交定义**：合同签署且首付款到账，客户阶段为"成交"
2. **业绩归属**：业绩归属于签约时的负责人（转移后成交，业绩归原负责人）
3. **时间维度**：统计按自然月/季度/年度计算（1月1日-1月31日为1月）
4. **转化率计算**：转化率 = 成交客户数 ÷ 潜在客户数 × 100%
