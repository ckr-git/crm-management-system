# 数据库设计文档

> 📌 本文档详细设计CRM系统的数据库结构，包括ER图、表结构、索引、关系等

---

## 📊 数据库设计原则

1. **范式设计**：遵循第三范式（3NF），减少数据冗余
2. **性能优先**：适当冗余提升查询性能（如存储客户最后跟进时间）
3. **扩展性**：预留扩展字段，支持后续功能迭代
4. **软删除**：重要数据采用软删除（deleted_at字段）
5. **时间戳**：所有表都有created_at和updated_at字段

## 📋 数据表设计

### 1. 用户表（users）

**表说明**：存储系统用户信息

```sql
CREATE TABLE `users` (
  `id` INT UNSIGNED AUTO_INCREMENT PRIMARY KEY COMMENT '用户ID',
  `username` VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名（手机号）',
  `password` VARCHAR(255) NOT NULL COMMENT '密码（BCrypt加密）',
  `name` VARCHAR(50) NOT NULL COMMENT '真实姓名',
  `email` VARCHAR(100) DEFAULT NULL COMMENT '邮箱',
  `avatar` VARCHAR(255) DEFAULT NULL COMMENT '头像URL',
  `role_id` INT UNSIGNED NOT NULL COMMENT '角色ID',
  `department_id` INT UNSIGNED DEFAULT NULL COMMENT '部门ID',
  `manager_id` INT UNSIGNED DEFAULT NULL COMMENT '直属上级ID',
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '状态：1启用 0停用',
  `last_login_at` DATETIME DEFAULT NULL COMMENT '最后登录时间',
  `last_login_ip` VARCHAR(50) DEFAULT NULL COMMENT '最后登录IP',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at` DATETIME DEFAULT NULL COMMENT '删除时间（软删除）',
  
  INDEX `idx_role_id` (`role_id`),
  INDEX `idx_department_id` (`department_id`),
  INDEX `idx_manager_id` (`manager_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

**字段说明：**
| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | INT | 主键 | 1 |
| username | VARCHAR(50) | 登录账号（手机号）| 13800138000 |
| password | VARCHAR(255) | 加密密码 | $2b$10$... |
| name | VARCHAR(50) | 真实姓名 | 张三 |
| role_id | INT | 角色ID | 2（销售人员）|
| status | TINYINT | 账号状态 | 1启用 0停用 |

### 2. 角色表（roles）

CREATE TABLE `roles` (

### 4. 客户表（customers）⭐核心表

**表说明**：存储客户基本信息和业务信息

```sql
CREATE TABLE `customers` (
  `id` INT UNSIGNED AUTO_INCREMENT PRIMARY KEY COMMENT '客户ID',
  `customer_no` VARCHAR(50) NOT NULL UNIQUE COMMENT '客户编号（C+年月日+4位流水号）',
  `name` VARCHAR(50) NOT NULL COMMENT '客户姓名',
  `phone` VARCHAR(11) NOT NULL UNIQUE COMMENT '手机号',
  `company` VARCHAR(100) NOT NULL COMMENT '公司名称',
  `company_phone` VARCHAR(20) DEFAULT NULL COMMENT '公司电话',
  `email` VARCHAR(100) DEFAULT NULL COMMENT '邮箱',
  `position` VARCHAR(50) DEFAULT NULL COMMENT '职位',
  `wechat` VARCHAR(50) DEFAULT NULL COMMENT '微信号',
  `qq` VARCHAR(20) DEFAULT NULL COMMENT 'QQ号',
  `address` VARCHAR(255) DEFAULT NULL COMMENT '公司地址',
  `website` VARCHAR(255) DEFAULT NULL COMMENT '公司网站',
  
  -- 业务信息
  `source` VARCHAR(50) DEFAULT NULL COMMENT '客户来源（字典：exhibition展会/website官网/phone电话/referral推荐/other其他）',
  `industry` VARCHAR(50) DEFAULT NULL COMMENT '所属行业（字典）',
  `stage` VARCHAR(50) NOT NULL DEFAULT 'lead' COMMENT '销售阶段（字典：lead潜在/prospect意向/qualified需求/negotiation洽谈/won成交/existing老客户）',
  `tags` JSON DEFAULT NULL COMMENT '客户标签（JSON数组）',
  `budget_range` VARCHAR(50) DEFAULT NULL COMMENT '预算范围（字典：<30k/30k-50k/50k-100k/>100k）',
  `expected_deal_date` DATE DEFAULT NULL COMMENT '期望成交日期',
  `requirement` TEXT DEFAULT NULL COMMENT '客户需求描述',
  `remark` TEXT DEFAULT NULL COMMENT '备注信息',
  
  -- 关系字段
  `owner_id` INT UNSIGNED NOT NULL COMMENT '负责人ID',
  `creator_id` INT UNSIGNED NOT NULL COMMENT '创建人ID',
  
  -- 统计字段（冗余，提升查询性能）
  `followup_count` INT NOT NULL DEFAULT 0 COMMENT '跟进次数',
  `last_followup_at` DATETIME DEFAULT NULL COMMENT '最后跟进时间',
  `last_followup_content` VARCHAR(500) DEFAULT NULL COMMENT '最后跟进内容',
  
  -- 公海池相关
  `in_pool` TINYINT NOT NULL DEFAULT 0 COMMENT '是否在公海池：1是 0否',
  `enter_pool_at` DATETIME DEFAULT NULL COMMENT '进入公海池时间',
  `enter_pool_reason` VARCHAR(255) DEFAULT NULL COMMENT '进入公海池原因',
  
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at` DATETIME DEFAULT NULL COMMENT '删除时间（软删除）',
  
  -- 索引优化
  INDEX `idx_customer_no` (`customer_no`),
  INDEX `idx_phone` (`phone`),
  INDEX `idx_owner_id` (`owner_id`),
  INDEX `idx_stage` (`stage`),
  INDEX `idx_source` (`source`),
  INDEX `idx_industry` (`industry`),
  INDEX `idx_in_pool` (`in_pool`),
  INDEX `idx_last_followup_at` (`last_followup_at`),
  INDEX `idx_created_at` (`created_at`),
  
  FULLTEXT INDEX `idx_fulltext` (`name`, `company`) -- 全文索引，用于模糊搜索
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='客户表';
```

### 5. 跟进记录表（followups）⭐核心表

**表说明**：记录每次客户跟进情况

```sql
CREATE TABLE `followups` (
  `id` INT UNSIGNED AUTO_INCREMENT PRIMARY KEY COMMENT '跟进记录ID',
  `customer_id` INT UNSIGNED NOT NULL COMMENT '客户ID',
  `user_id` INT UNSIGNED NOT NULL COMMENT '跟进人ID',
  `type` VARCHAR(50) NOT NULL COMMENT '沟通方式（phone电话/wechat微信/email邮件/visit拜访/other其他）',
  `content` TEXT NOT NULL COMMENT '沟通内容',
  `feedback` TEXT DEFAULT NULL COMMENT '客户反馈',
  `next_plan` VARCHAR(500) DEFAULT NULL COMMENT '下次跟进计划',
  `next_followup_at` DATETIME DEFAULT NULL COMMENT '下次跟进时间',
  `stage_before` VARCHAR(50) DEFAULT NULL COMMENT '跟进前阶段',
  `stage_after` VARCHAR(50) DEFAULT NULL COMMENT '跟进后阶段',
  `attachments` JSON DEFAULT NULL COMMENT '附件列表（JSON数组）',
  `followup_at` DATETIME NOT NULL COMMENT '本次跟进时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at` DATETIME DEFAULT NULL COMMENT '删除时间（软删除）',
  
  INDEX `idx_customer_id` (`customer_id`),
  INDEX `idx_user_id` (`user_id`),
  INDEX `idx_followup_at` (`followup_at`),
  INDEX `idx_next_followup_at` (`next_followup_at`),
  
  FOREIGN KEY (`customer_id`) REFERENCES `customers` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='跟进记录表';
```

### 6. 销售机会表（opportunities）

**表说明**：销售机会（商机）信息

```sql
CREATE TABLE `opportunities` (
  `id` INT UNSIGNED AUTO_INCREMENT PRIMARY KEY COMMENT '销售机会ID',

  `owner_id` INT UNSIGNED NOT NULL COMMENT '负责人ID',

  `stage` VARCHAR(50) NOT NULL COMMENT '销售阶段',

  `expected_close_date` DATE DEFAULT NULL COMMENT '预计成交日期',
  `priority` TINYINT NOT NULL DEFAULT 2 COMMENT '优先级：1高 2中 3低',
  `description` TEXT DEFAULT NULL COMMENT '机会描述',
  `competitors` VARCHAR(500) DEFAULT NULL COMMENT '竞争对手',
  `status` VARCHAR(50) NOT NULL DEFAULT 'open' COMMENT '状态：open进行中/won赢单/lost输单',
  `win_reason` VARCHAR(500) DEFAULT NULL COMMENT '赢单原因',
  `lost_reason` VARCHAR(500) DEFAULT NULL COMMENT '输单原因',
  `actual_amount` DECIMAL(15,2) DEFAULT NULL COMMENT '实际成交金额',
  `close_date` DATE DEFAULT NULL COMMENT '成交日期',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at` DATETIME DEFAULT NULL COMMENT '删除时间（软删除）',
  
  INDEX `idx_customer_id` (`customer_id`),
  INDEX `idx_owner_id` (`owner_id`),
  INDEX `idx_stage` (`stage`),
  INDEX `idx_status` (`status`),
  INDEX `idx_expected_close_date` (`expected_close_date`),
  
  FOREIGN KEY (`customer_id`) REFERENCES `customers` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='销售机会表';
```

## 🔗 表关系说明

### 一对多关系

1. **用户 → 客户**（一个用户负责多个客户）
   - `users.id` ← `customers.owner_id`

2. **客户 → 跟进记录**（一个客户有多条跟进记录）
   - `customers.id` ← `followups.customer_id`

3. **客户 → 销售机会**（一个客户有多个销售机会）
   - `customers.id` ← `opportunities.customer_id`

4. **用户 → 跟进记录**（一个用户创建多条跟进记录）
   - `users.id` ← `followups.user_id`

### 多对多关系

1. **用户 ↔ 角色**（一个用户可以有多个角色，实际CRM中通常一对一）
   - 通过 `users.role_id` 关联

## 📊 索引优化策略

### 1. 单列索引
- **主键索引**：所有表的`id`字段（自动创建）
- **唯一索引**：`customers.phone`、`users.username`、`customers.customer_no`
- **普通索引**：外键字段、常用查询字段

### 2. 组合索引
```sql
-- 客户列表查询优化（按负责人+阶段+创建时间）
ALTER TABLE `customers` ADD INDEX `idx_owner_stage_created` (`owner_id`, `stage`, `created_at`);

-- 跟进记录查询优化（按客户+跟进时间）
ALTER TABLE `followups` ADD INDEX `idx_customer_followup` (`customer_id`, `followup_at`);
```

### 3. 全文索引
```sql
-- 客户名称和公司名称模糊搜索
ALTER TABLE `customers` ADD FULLTEXT INDEX `idx_fulltext` (`name`, `company`);
```

## 🚀 性能优化建议

### 1. 冗余字段
为了提升查询性能，在`customers`表中冗余了以下字段：
- `followup_count`：跟进次数（避免每次COUNT查询）
- `last_followup_at`：最后跟进时间（用于列表排序和超期判断）
- `last_followup_content`：最后跟进内容（列表展示，避免JOIN查询）

**维护方式**：在添加跟进记录时，通过触发器或应用层代码同步更新

### 2. 分区表（数据量大时）
当`operation_logs`表数据量超过1000万条时，可以考虑按月分区：
```sql
ALTER TABLE `operation_logs` PARTITION BY RANGE (YEAR(created_at) * 100 + MONTH(created_at)) (
  PARTITION p202501 VALUES LESS THAN (202502),
  PARTITION p202502 VALUES LESS THAN (202503),
  -- ...
);
```

### 3. 读写分离
- **主库**：处理写操作（INSERT、UPDATE、DELETE）
- **从库**：处理读操作（SELECT）
- 使用中间件（如ProxySQL）或应用层路由

## 🔧 数据库维护

### 1. 备份策略
- **全量备份**：每天凌晨2点自动备份
- **增量备份**：每4小时备份binlog
- **保留策略**：全量备份保留30天，增量备份保留7天

### 2. 数据清理
- **操作日志**：保留最近6个月，超过6个月归档或删除
- **软删除数据**：定期清理1年前的软删除数据

### 3. 性能监控
- 使用`EXPLAIN`分析慢查询
- 定期优化表：`OPTIMIZE TABLE customers;`
- 监控索引使用情况
