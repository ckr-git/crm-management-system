# 技术术语解释

> 📌 本文档用通俗易懂的语言解释CRM项目中涉及的技术术语，帮助新手理解

---

## 🌐 Web开发基础

### 前端（Frontend）
**什么是**：用户能看到和操作的界面部分，运行在浏览器中

**通俗解释**：就像餐厅的前厅，客户能看到菜单、座位、装修

**例子**：你在网页上看到的按钮、表单、图表、颜色、布局

---

### 后端（Backend）
**什么是**：服务器端的程序，处理业务逻辑和数据

**通俗解释**：就像餐厅的后厨，客户看不见但在处理订单和做菜

**例子**：验证用户登录、查询客户数据、保存跟进记录

---

### 数据库（Database）
**什么是**：存储数据的地方

**通俗解释**：就像一个巨大的Excel表格，但功能更强大

**例子**：用户信息表、客户信息表、跟进记录表

---

### API（Application Programming Interface，应用程序接口）
**什么是**：前端和后端之间沟通的桥梁

**通俗解释**：就像餐厅的传菜口，前厅服务员把订单传给后厨，后厨做好菜传给服务员

**例子**：
- 前端：点击"登录"按钮 → 调用登录API
- 后端：验证账号密码 → 返回"登录成功"或"密码错误"

---

### HTTP/HTTPS
**什么是**：浏览器和服务器之间传输数据的协议

**通俗解释**：就像快递公司规定的包裹配送规则

**区别**：
- HTTP：明文传输，不安全（就像明信片，别人能看到内容）
- HTTPS：加密传输，安全（就像密封的快递包裹）

---

### 前后端分离
**什么是**：前端和后端独立开发、独立部署

**通俗解释**：前厅和后厨分开运作，互不干扰但通过传菜口沟通

**优点**：
- 前端和后端可以同时开发，提高效率
- 前端可以随意换设计，不影响后端
- 一个后端可以支持网页、APP、小程序多个前端

---

## 🎨 前端技术

### Vue 3
**什么是**：前端框架，用于构建用户界面

**通俗解释**：就像搭积木的工具箱，帮你快速搭建界面

**为什么用**：
- 写代码更快（提供了很多现成的功能）
- 数据变化时界面自动更新（不需要手动刷新）
- 社区活跃，遇到问题容易找到答案

**例子**：
```javascript
// 不用Vue：手动修改网页内容
document.getElementById('name').innerText = '张三'

// 用Vue：数据变化自动更新界面
name.value = '张三' // 界面自动显示"张三"
```

---

### 组件（Component）
**什么是**：可复用的界面片段

**通俗解释**：就像乐高积木块，每个积木块可以单独制作，然后组装成完整的作品

**例子**：
- 导航栏组件（在多个页面复用）
- 按钮组件（在多个地方复用）
- 客户卡片组件（客户列表中每个卡片）

---

### 单页应用（SPA，Single Page Application）
**什么是**：整个网站只有一个HTML文件，切换页面不刷新浏览器

**通俗解释**：就像看书翻页，只是内容变了，书本身没变

**优点**：
- 切换页面非常快（不需要重新加载整个页面）
- 用户体验好（像APP一样流畅）

**例子**：Gmail、微信网页版

---

### 路由（Router）
**什么是**：管理不同网址对应显示哪个页面

**通俗解释**：就像导航系统，告诉你"去客户列表页"该显示什么内容

**例子**：
- `/login` → 显示登录页面
- `/customer/list` → 显示客户列表页面
- `/customer/detail/123` → 显示ID为123的客户详情页面

---

### 状态管理（State Management）
**什么是**：管理应用程序的数据状态

**通俗解释**：就像电脑的内存，临时存储当前用户信息、登录状态等数据

**为什么需要**：
- 多个页面需要共享数据（比如用户信息）
- 避免重复请求（数据缓存在状态管理中）

**例子**：
- 用户登录后，用户信息存储在状态管理中
- 所有页面都能读取当前登录用户的姓名、权限等

---

### Element Plus
**什么是**：Vue 3 的UI组件库

**通俗解释**：就像宝藏箱，里面有按钮、表格、表单等做好的漂亮组件，直接拿来用

**例子**：
- `<el-button>` - 按钮组件
- `<el-table>` - 表格组件
- `<el-form>` - 表单组件

---

## 🖥️ 后端技术

### Node.js
**什么是**：让JavaScript运行在服务器端的环境

**通俗解释**：JavaScript原本只能在浏览器运行，Node.js让它可以在服务器运行

**为什么用**：
- 前后端都用JavaScript，学习成本低
- 异步IO性能好，适合高并发场景
- 生态丰富（NPM有100万+个包）

---

### Express
**什么是**：Node.js的Web框架

**通俗解释**：就像脚手架，帮你快速搭建后端服务器

**例子**：
```javascript
// 定义一个API接口
app.get('/api/customers', (req, res) => {
  // 查询客户列表
  res.json({ code: 200, data: customerList })
})
```

---

### RESTful API
**什么是**：一种设计API的规范

**通俗解释**：就像快递公司的标准操作流程，大家都按这个规则来

**核心规则**：
- GET：查询数据（不修改数据）
- POST：创建新数据
- PUT：完整更新数据
- PATCH：部分更新数据
- DELETE：删除数据

**例子**：
- `GET /api/customers` - 获取客户列表
- `POST /api/customers` - 创建新客户
- `PUT /api/customers/123` - 更新ID为123的客户
- `DELETE /api/customers/123` - 删除ID为123的客户

---

### 中间件（Middleware）
**什么是**：请求处理过程中的拦截器

**通俗解释**：就像机场安检，每个乘客上飞机前都要经过安检

**例子**：
```javascript
// 身份验证中间件
app.use((req, res, next) => {
  if (req.headers.token) {
    next() // 有Token，放行
  } else {
    res.status(401).json({ message: '未登录' })
  }
})
```

---

### ORM（Object-Relational Mapping，对象关系映射）
**什么是**：用面向对象的方式操作数据库

**通俗解释**：不需要写SQL语句，用JavaScript代码就能操作数据库

**例子**：
```javascript
// 不用ORM：写SQL语句
const sql = 'SELECT * FROM customers WHERE name = "张三"'
db.query(sql)

// 用ORM（Sequelize）：用JavaScript代码
Customer.findOne({ where: { name: '张三' } })
```

## 🗄️ 数据库相关

### SQL
**什么是**：操作关系型数据库的语言

**通俗解释**：就像Excel的筛选、排序功能，但功能更强大

**例子**：
```sql
-- 查询所有客户
SELECT * FROM customers;

-- 查询姓名是"张三"的客户
SELECT * FROM customers WHERE name = '张三';

-- 按创建时间倒序排列
SELECT * FROM customers ORDER BY created_at DESC;
```

---

### 主键（Primary Key）
**什么是**：表中每行数据的唯一标识

**通俗解释**：就像身份证号，每个人都有唯一的一个

**例子**：客户表中的 `id` 字段

---

### 外键（Foreign Key）
**什么是**：表示表与表之间的关联关系

**通俗解释**：就像学生证上的学号，可以关联到学生信息表

**例子**：
- 客户表的 `owner_id` 关联用户表的 `id`
- 表示这个客户由哪个销售负责

---

### 索引（Index）
**什么是**：加速查询的数据结构

**通俗解释**：就像书的目录，不需要翻遍整本书就能快速找到内容

**为什么需要**：
- 数据库有10万条客户数据
- 没有索引：需要逐条查找，很慢
- 有索引：像查字典一样，秒级找到

**例子**：
- 客户表的 `phone` 字段建立索引
- 查询手机号为"13800138000"的客户，速度快100倍

---

### 软删除（Soft Delete）
**什么是**：删除时不真正删除数据，只是标记为"已删除"

**通俗解释**：就像把文件放进回收站，而不是永久删除

**为什么需要**：
- 防止误删（可以恢复）
- 保留历史记录（审计需要）

**例子**：
- 客户表有 `deleted_at` 字段
- 删除客户时，设置 `deleted_at = 当前时间`
- 查询时，只查询 `deleted_at IS NULL` 的数据

---

### 事务（Transaction）
**什么是**：一组数据库操作，要么全部成功，要么全部失败

**通俗解释**：就像银行转账，扣钱和加钱必须同时成功，否则都不执行

**例子**：
- 转移客户操作：
  1. 将客户的 `owner_id` 改为新销售
  2. 记录转移日志
  3. 如果任何一步失败，两步都回滚

---

## 🔐 安全相关

### 身份认证（Authentication）
**什么是**：验证用户是谁

**通俗解释**：就像门禁系统刷卡，确认你是这个小区的业主

**例子**：用户输入账号密码登录

---

### 授权（Authorization）
**什么是**：验证用户有没有权限做某件事

**通俗解释**：就像确认你是业主后，还要看你有没有停车位的权限

**例子**：
- 销售人员只能查看自己的客户
- 销售经理可以查看团队所有客户

---

### Token（令牌）
**什么是**：用户登录后服务器颁发的凭证

**通俗解释**：就像游乐场的手环，证明你已经买票进场

**流程**：
1. 用户登录成功
2. 服务器生成Token返回给用户
3. 用户后续请求都带上Token
4. 服务器验证Token，确认用户身份

---

### JWT（JSON Web Token）
**什么是**：一种Token的实现方式

**通俗解释**：就像加密的身份证，包含用户信息且不可篡改

**结构**：
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9  // 头部
.eyJ1c2VySWQiOjEsInJvbGUiOiJhZG1pbiJ9  // 负载（用户信息）
.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV  // 签名
```

**优点**：
- 无状态（服务器不需要存储Token）
- 跨域友好

---

### 加密（Encryption）
**什么是**：把明文变成密文，防止泄露

**通俗解释**：就像把信件装进保险箱，只有有钥匙的人能打开

**例子**：
- 密码加密：123456 → $2b$10$K8YQX.5a7O5ZqV5J...
- 即使数据库泄露，黑客也无法破解密码

---

### HTTPS
**什么是**：加密的HTTP协议

**通俗解释**：就像邮寄快递用密封包裹，而不是明信片

**为什么需要**：
- 防止数据被窃听（比如密码、银行卡号）
- 防止中间人攻击

---

## 🚀 部署相关

### 服务器（Server）
**什么是**：运行后端程序的计算机

**通俗解释**：就像餐厅的后厨，24小时运转

**云服务器**：
- 阿里云、腾讯云、华为云
- 按配置付费（2核4G约100元/月）

---

### Nginx
**什么是**：Web服务器和反向代理

**通俗解释**：就像餐厅的前台接待，负责接待客人并分配到不同的服务员

**作用**：
- 托管前端静态文件
- 将API请求转发到后端服务
- 负载均衡（多台服务器分流）

---

### PM2
**什么是**：Node.js进程管理工具

**通俗解释**：就像保姆，后端程序崩溃了自动重启

**作用**：
- 进程守护（自动重启）
- 日志管理
- 负载均衡（利用多核CPU）

---

### 域名（Domain Name）
**什么是**：网站的网址

**通俗解释**：就像房子的门牌号

**例子**：www.example.com

---

### SSL证书
**什么是**：实现HTTPS加密的证书

**通俗解释**：就像营业执照，证明你是合法网站

**获取**：
- 免费：Let's Encrypt
- 付费：阿里云、腾讯云

## 📊 其他术语

### 响应式设计（Responsive Design）
**什么是**：网页自动适配不同屏幕大小

**通俗解释**：在电脑上看是大屏布局，在手机上看是小屏布局

---

### 懒加载（Lazy Loading）
**什么是**：需要时才加载数据或图片

**通俗解释**：就像滚动刷微信朋友圈，只加载看得见的图片

**优点**：加快页面加载速度

---

### 防抖（Debounce）
**什么是**：短时间内多次触发，只执行最后一次

**通俗解释**：就像电梯门，有人进来就重新计时，直到没人进了才关门

**例子**：
- 搜索框输入，停止输入300ms后才发起搜索请求
- 避免每输入一个字就发一次请求

---

### 节流（Throttle）
**什么是**：一定时间内只执行一次

**通俗解释**：就像水龙头限流，不管多用力拧，水流速度固定

**例子**：
- 滚动加载，每100ms最多触发一次
- 避免滚动太快导致性能问题

---

### 缓存（Cache）
**什么是**：临时存储数据，减少重复请求

**通俗解释**：就像把常用的东西放在桌面上，不用每次都去柜子里翻

**例子**：
- 字典数据（客户来源、行业）缓存在Redis
- 不需要每次都查数据库
